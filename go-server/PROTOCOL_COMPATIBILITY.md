# v1.0.8 Go 服务端：Python 客户端协议适配

本次适配保持现有 RSA-OAEP/AES-GCM、长度头与 JSON 编码、认证流程和默认端口 `12346`，沿用原数据库，不需要迁移。

| 请求或事件 | 新行为 |
| --- | --- |
| `private_chat` / `group_chat` | 接受 `request_id`；数据库保存成功才返回同类型 `_result`，包含 `success: true`、原 `request_id` 和提交后的 `message_id`。校验、解密、包大小及数据库失败返回同请求 ID 的失败响应。 |
| 实时与历史聊天消息 | 使用相同的 SQLite `message_id`，支持客户端去重、排序及重连后识别同一条记录。 |
| 登录后的历史同步 | `history_begin` 开始，全部会话共享一个最大 ID 边界；单次查询按 ID 排序，过滤非好友私聊及非成员群聊；`history_end` 包含边界。读取或发送失败会终止本次登录同步。 |
| `group_invite_response` | `accepted: false` 删除当前响应者的待处理邀请，返回 `group_invite_response_result`。接受继续使用 `group_join`；已有 24 小时过期检查保留。 |
| 解散、转让、改名 | 操作者仅收到操作结果，其他成员收到通知；改名结果包含 `old_name` 和 `new_name`。 |
| 已登录连接的发送 | 在每个连接中序列化不可变帧并排队，群锁内不等待网络写入；保持同一连接的帧顺序。队列满或写超时关闭连接。 |

保存确认代表数据库已经提交，不代表接收者已读或一定已在线收到。转发失败不会将已保存的消息改报为保存失败，离线接收者可重新登录读取历史。

认证响应同步发送，然后才启用发送队列并公开在线会话，保留重复登录保护及首包必须为登录响应的约束。历史发送在群操作锁外使用有界回压，避免快速加载历史把正常连接的队列直接挤满。

验证覆盖：提交后的 ID、失败响应关联及不转发、历史 ID/全局排序/旧库 NULL 列、邀请拒绝及再邀请、管理通知去重、包大小、发送队列快照与顺序、队列拥塞、写超时，以及真实 v1.0.7 Tk 客户端确认后清空输入。Go 单元测试、静态检查、Windows 数据竞争检测和 5 项真实网络互操作测试均通过。

Go v1.0.8 包含这些协议行为；旧版 Go v1.0.6 二进制不支持新增消息保存确认。待处理邀请仍在内存中，历史仍全量加载。
