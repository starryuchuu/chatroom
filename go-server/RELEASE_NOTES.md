# v1.4.0 — 历史分页请求关联

- 新增可选的 `history_request_id` 能力：分页控制帧回传请求 ID，历史消息携带关联标记，允许新版客户端区分超时后的晚到响应与重试请求；未携带 ID 的旧客户端请求继续受支持。
- 请求 ID 必须是 1–128 个有效 UTF-8 字符；非法输入返回参数错误后保持连接可重试。接近帧大小上限时可省略逐条标记，并由客户端根据批次控制帧判断归属。
- 配套 Python 客户端统一连接、账号、会话与群成员代次校验，增加 20 秒分页超时处理及消息列表窗口渲染；建议两端一起升级。
- 数据库结构、传输 v2、OPAQUE、存储加密和端到端密钥格式不变，已有 OPAQUE 账号无需再次迁移。升级前停止旧进程并备份数据库、对应存储密钥和 RSA 身份。
- 本地完整 506 项 Python、真实 Tk 和双服务端互操作回归通过；Go 静态检查及竞态检测通过。完整更新见[项目发布说明](../RELEASE_NOTES.md)。

# v1.3.0 — OPAQUE 单密码认证与身份备份

- 与 Python 共用固定 `opaque-ke=4.0.1` WebAssembly 核心，由 `wazero` 执行；采用 RFC 9807 OPAQUE，新增 `opaque_v1` 能力。上游历史审计不代表该版本或本项目集成经过独立审计。
- 新注册与已迁移账号使用 OPAQUE，服务端不接收正常认证或改密的明文密码。新增受存储密钥保护的 `opaque_meta` / `opaque_accounts`，持久保存 setup、账号记录、身份备份和更新代次。已存在 OPAQUE 账号但 setup 缺失时停止启动。
- 显式旧账号迁移先验证经认证传输保护的旧登录密码，再以 CAS 原子替换旧记录；客户端还需原本机密钥口令与新统一密码，保留原端到端身份。迁移后拒绝该账号的旧客户端认证。
- 修改密码使用独立短连接，先验证当前 OPAQUE 凭据，再以代次 CAS 更新新记录和同一身份的加密备份，不占用重复在线会话。
- 云端备份仅含加密身份，不同步联系人信任、群批准和重放记录；本机 v2 分层密钥库可在改密后验证并保留原本机信任。完整离线备份仍由统一密码经 Argon2id 加密，改密后应重新导出。
- 先备份数据库、存储密钥、RSA 身份及客户端离线备份，再升级服务端与客户端。新版客户端要求 `opaque_v1` 和 `e2ee_v1`，拒绝旧服务器；未迁移账号的旧协议兼容仍受既有端到端降级限制。不要用旧服务端打开升级后的数据库。
- 普通 Go 构建使用内嵌的预编译 WASM，无需 Rust；重建核心需 Rust 1.87+，从仓库根目录执行 `python scripts/build_opaque.py`。Python 侧新增 `wasmtime==50.0.1`。

传输协议 v2、端到端消息封装、群接收人核对及无长期前向保密的限制继续使用。忘记密码并失去所有可用恢复材料时，没有服务器恢复保证。完整说明见[项目发布说明](../RELEASE_NOTES.md)、[单密码指南](../docs/SINGLE_PASSWORD.md)及[协议兼容性](PROTOCOL_COMPATIBILITY.md)。

# v1.1.0 — 断线增量同步与配套客户端功能

- 握手声明 `message_sync` 能力，支持 `sync_request` 在固定消息边界内前向分页补取全部遗漏消息，每页最多 100 条，超过一页的断线消息也可恢复。
- 每页只返回当前有权读取的私聊与群消息，群消息排队前再次校验成员资格；开始和完成事件关联请求 ID、起点与边界，失败不会确认已完成。
- 历史消息携带可选回放标记，防止客户端将历史补取误报为实时桌面提醒。新消息预留回放元数据空间；旧版近报文上限的记录保留正文及 ID，必要时省略可选标记。
- 配套 Python 客户端增加服务器配置、未读/最近消息、桌面提醒与免打扰、可取消的自动重连。配置不保存密码或正文。

帧协议 v2 和存储格式 v1 不变，无需数据库迁移；兼容 v1.0.10–v1.0.17 客户端。完整自动补取需使用 v1.1.0 客户端及服务端。详情见[完整发布说明](../RELEASE_NOTES.md)与[协议说明](PROTOCOL_COMPATIBILITY.md)。
