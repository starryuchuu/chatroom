## 📖 项目简介

本项目提供私聊、群聊、好友及群组管理。v1.3.1 桌面客户端支持即时切换的**深色 / 浅色模式**，并沿用 v1.3.0 引入的 OPAQUE **单密码登录**，用一份统一密码解锁随机端到端身份，无需另设本机口令。新消息使用 Ed25519、X25519 与 AES-256-GCM 进行**端到端加密**，服务端仅保存和转发密文。原有 RSA 会话密钥交换与 HMAC-SHA256 完整报文认证继续保护连接；数据库敏感字段仍加密存储。旧历史保留并明确标记为非端到端加密，详见[端到端加密与密钥恢复](docs/END_TO_END_ENCRYPTION.md)。

### ✨ 核心优势

- **🔒 通信保护**：RSA-3072 密钥交换 + AES-GCM 正文加密 + 完整报文认证
- **🔑 端到端加密**：客户端签名、逐接收人密钥封装、联系人指纹固定、加密身份恢复与完整离线备份
- **🛡️ 单密码认证**：OPAQUE 注册、登录和改密不向服务器发送明文统一密码；旧账号显式迁移
- **🔐 服务器身份校验**：远程连接必须校验服务端公钥指纹（SHA-256）
- **💬 丰富功能**：支持私聊、群聊、好友管理、群组管理
- **💾 数据持久化**：SQLite 数据库存储聊天记录和用户信息
- **🚀 双服务端**：Python 和 Go 两种实现，满足不同需求

## 🚀 快速开始

### 环境要求

- **Python 客户端 / 服务端**: Python 3.11+
- **Go 服务端**: Go 1.24+（`go.mod` 指定 toolchain `go1.24.5`）
- **操作系统**: Windows / Linux / macOS

### 安装依赖

```bash
pip install -r requirements.txt
```

普通源码包包含预编译的 OPAQUE WASM；Python 新增 `wasmtime==50.0.1`，无需 Rust。Go 使用 `wazero` 运行内嵌的同一核心。仅修改并重建核心的开发者需要 Rust 1.87+，详见[单密码指南](docs/SINGLE_PASSWORD.md)。

### 启动服务端

#### 方式一：Python 服务端（端口 12345）

```bash
python server.py
```

> - 首次启动时会自动生成 RSA-3072 密钥对（`private_key.pem` 和 `public_key.pem`）
> - 两端服务端都保留已有身份：仅私钥丢失而公钥仍存在时会停止启动，需恢复原私钥；不要通过删除公钥绕过恢复
> - 默认仅监听 `127.0.0.1`（本机回环），如需对外提供服务，请修改 `server.py` 中的 `SERVER_BIND_HOST`

#### 方式二：Go 服务端（端口 12346）

**Windows:**
```bash
cd go-server
start.bat
```

> 也可从 [v1.3.1 发布页](https://github.com/starryuchuu/chatroom/releases/tag/v1.3.1) 下载相应平台的 Go 服务端可执行文件；源码仓库不包含预编译服务端可执行文件。

**Linux/macOS:**（需先编译）
```bash
cd go-server
go build -o chatroom-server ./cmd/server/main.go
./chatroom-server
```

> Go 服务端默认仅监听 `127.0.0.1:12346`。

### 启动客户端

```bash
python client.py
```

### 客户端连接配置

登录页可直接选择服务器，点击 **连接设置…** 新增、编辑或删除配置，填写地址、端口及公钥指纹后保存并使用。内置本机 Python（`127.0.0.1:12345`）和 Go（`127.0.0.1:12346`）配置，打包程序同样可用，无需修改源码。登录页的端口输入仅覆盖本次连接；要长期保存端口，请编辑服务器配置。

连接远程服务器必须填写通过可信渠道核实的 SHA-256 公钥指纹。配置窗口接受 64 位十六进制指纹，也会规范化带冒号或空格的指纹。连接、认证或重连期间不能切换服务器。

首次启动仍使用 `client.py` 顶部常量作为默认值；已有保存配置时，以所选配置为准。配置文件为 Windows `%APPDATA%/Chatroom/client.json`、Linux `$XDG_CONFIG_HOME/chatroom/client.json`（未设置时为 `~/.config/chatroom/client.json`）、macOS `~/Library/Application Support/Chatroom/client.json`。可用 `CHATROOM_CONFIG_DIR` 指定其他目录。

### 深色与浅色模式

登录页和聊天页右上角的按钮显示将要切换的模式：点击 **深色模式** 启用深色，点击 **浅色模式** 切回浅色。切换立即应用于主窗口和已打开的应用对话框，不重新登录，不清空输入或草稿。系统原生文件选择器和消息框的外观由操作系统管理。

主题保存在 `client.json` 顶层的 `theme` 字段，仅接受 `light` / `dark`；未设置时默认 `light`。主题由用户手动选择，不自动跟随系统。保存失败会提示错误并保留原主题。

登录页使用居中表单卡片；高 DPI 或窗口高度不足时可滚动，Tab 键聚焦的操作会自动进入可见区域。聊天侧栏按实际宽度省略过长摘要，完整消息仍在会话中显示。

### 未读消息与提醒

好友和群列表显示未读数与最近消息预览，窗口标题显示总未读数。打开会话且窗口处于前台时清除未读；窗口在后台或最小化时继续累计。首次使用账号时，最近历史作为基线，不会将旧消息批量提醒；之后会恢复按服务器和账号隔离的已读位置与未读编号。

聊天页顶部的 **通知设置** 菜单可开关 **消息提醒** 或 **免打扰**。免打扰保留未读数，不发送通知或提示音。桌面通知只显示通用的新消息提示，不包含正文；不为历史或断线补取消息逐条弹窗。Windows 使用系统通知图标提示，Linux 使用 `notify-send`，macOS 使用系统通知；系统能力不可用时退回窗口提示音。Linux 可安装 `libnotify-bin` 以启用桌面通知。

本地设置只保存服务器配置、主题、提醒偏好、账号标识和消息编号，不保存密码、聊天正文或草稿。多个客户端同时保存时，会在文件锁内读取最新设置再更新，保留其他账号和服务器配置。草稿在当前进程中按服务器和账号隔离保留，关闭进程后不保留。

点击顶部 **在线用户** 可展开或收起在线列表。输入框中按 Enter 发送，Shift+Enter 或 Ctrl+Enter 换行。

### 端到端加密与密钥

单密码认证需 v1.3.0 或更新的服务端和客户端。正常注册、登录只输入一份统一密码（新密码 8–128 个字符），通过 OPAQUE 认证解锁随机生成的端到端身份。旧账号先点击登录页 **迁移旧账号…**，输入旧登录密码、原本机密钥口令和新的统一密码；原私钥缺失或身份不符时停止，不替换已有身份。旧登录密码仅在这次显式迁移中经加密传输交给服务端验证。若服务端已提交迁移、本机仍是旧 v1 密钥文件，点击 **解锁旧密钥…** 输入原本机口令，再以新统一密码正常登录，保留本机信任，无需重复迁移。

聊天页 **加密与密钥…** 可核对指纹、**修改账号密码…** 或 **导出加密密钥备份…**。新设备可在正确认证后恢复云端加密身份，但云备份不包含联系人信任、群接收人批准或重放记录，仍需重新核对。本机 v2 分层密钥库可在另一设备改密后验证并保留原信任，云端不会覆盖或回滚这些记录。

完整离线备份仍由导出时的统一密码经 Argon2id + AES-GCM 保护，原 v1 备份可导入；直接复制 v2 本机文件不是独立离线密码备份。改密后旧导出文件仍需旧密码，请重新导出。统一密码及所有可用恢复材料全部丢失后，没有服务器恢复账号或历史端到端消息的保证。

联系人也需建立加密身份，否则保留输入并停止发送。首次信任需要独立渠道核对，联系人密钥变化会停止发送，群接收人变化需要明确确认。本协议不提供长期接收私钥后来泄露时的前向保密，服务端仍可观察路由与群成员等元数据。迁移和恢复步骤见[单密码指南](docs/SINGLE_PASSWORD.md)，群历史及保护范围见[端到端加密文档](docs/END_TO_END_ENCRYPTION.md)。

### 断线自动重连

异常断线后保留聊天界面和输入，按 1、2、4、8、15、30 秒重试，之后间隔保持 30 秒；可随时点击 **取消重连**。认证信息只保存在进程内，手动断开、取消或关闭客户端会清除。密码错误、服务器身份不匹配等认证失败会停止自动重连，要求重新登录。

在支持 `message_sync` 的新版 Python 或 Go 服务端上，重新连接会按固定历史边界分页补取全部遗漏消息，超过 100 条也可恢复，并按消息 ID 去重。补取失败可点击 **重试补取**，已完成的同步位置不会被半页结果覆盖。未收到保存确认的发送结果仍可能已经写入数据库，客户端保留输入供查看历史后确认，不自动重发。

传输协议 v2、存储加密格式 v1 和端到端消息封装保持不变。v1.3.1 客户端沿用 v1.3.0 的认证要求，要求服务端支持 `opaque_v1` 与 `e2ee_v1`，缺少能力时拒绝连接，不回退旧认证。服务端新增 `opaque_meta` 与 `opaque_accounts`；已有 OPAQUE 账号但 setup 缺失时停止启动。尚未迁移账号保留显式旧协议兼容，已迁移账号拒绝旧认证。升级前备份数据库、存储密钥、RSA 身份及客户端离线密钥备份，不要用旧服务端运行升级后的数据库。

## ⚙️ 配置说明

### 持久化申请与分页

`pending_friend_requests` 和 `pending_group_invites` 保存待处理申请与邀请，服务器启动时恢复，24 小时后过期。接受或拒绝后删除记录；好友接受和入群会在同一数据库事务中消费申请。旧数据库在启动时自动增加这两张表及消息查询索引。

登录时加载最近 100 条有权访问的消息。选中会话后点击“更早的消息”，按消息 ID 向前读取最多 100 条；每页再次校验访问权限。

`opaque_meta` 保存持久 OPAQUE setup，`opaque_accounts` 保存加密的账号记录、身份备份及更新代次。它们与数据库和对应存储密钥一起备份；不能为已有 OPAQUE 账号生成替代 setup。

### 默认端口

| 服务端 | 监听地址 | 端口 |
|--------|----------|------|
| Python 服务端 | 127.0.0.1 | 12345 |
| Go 服务端 | 127.0.0.1 | 12346 |

> 两个服务端默认**仅监听本机回环地址**（`127.0.0.1`），防止外部访问。

### 安全参数

| 参数 | 值 | 说明 |
|------|-----|------|
| RSA 密钥长度 | 3072 位 | 服务端密钥对 |
| 单条消息上限 | 1 MiB | 包含 40 字节序号和认证标签，超限断开 |
| 同时连接上限 | 128 | Python / Go 均限制连接数 |
| 同时认证上限 | 4 | 限制完整 OPAQUE / 旧认证交换的昂贵计算并发 |
| 认证阶段超时 | 30 秒 | 未完成认证的连接将被关闭 |
| 会话空闲超时 | 30 分钟 | 登录后空闲连接自动断开 |
| 登录速率限制 | 5 次 / 60 秒 | 防止暴力破解 |
| 用户名长度 | 2 ~ 20 字符 | 服务端强制校验 |
| 新统一密码长度 | 8 ~ 128 字符 | 客户端与认证辅助层校验；旧凭据沿用原限制 |
| 会话密钥 | AES-GCM 动态生成 | 每次登录重新协商 |

### 重要规则

- 🔐 聊天正文和凭据经 AES-GCM 加密；建立会话密钥后的所有报文均认证，元数据可见但不可被未持有密钥者篡改
- 🔑 新账号使用 OPAQUE 记录；正常注册、登录和改密不发送明文统一密码，旧账号哈希仅用于尚未迁移账号
- 👥 好友关系为双向绑定
- 👑 群主不能直接退出群聊，需先解散或转让
- 💾 数据库文件（`chat.db`）在首次运行时自动创建
- 🗝️ 私钥文件与数据库文件权限默认设为 0600（仅所有者可读写）

## ❓ 常见问题

### 连接问题

**Q: 端口被占用怎么办？**  
A: 检查是否有其他程序占用端口，或修改服务端端口配置（`server.py` / `main.go` 中的端口常量）。

**Q: 连接失败？**  
A: 确认服务端已启动，检查防火墙设置和网络连接。同时确认客户端端口与服务端一致（Python 服务端 `12345`，Go 服务端 `12346`）。

**Q: 客户端提示"未配置服务器公钥指纹"并拒绝连接？**  
A: 通过可信渠道取得服务器实际指纹，在登录页“连接设置…”中保存。不能使用未经核实的远程响应代替指纹核对；首次启动默认值也可通过 `EXPECTED_SERVER_KEY_FINGERPRINT` 配置。

**Q: 如何连接 Go 服务端？**  
A: 启动新版 Go 服务端后，在登录页选择本机 Go 配置，或通过“连接设置…”填写其地址、`12346` 端口及可信公钥指纹。

### 数据库问题

**Q: 数据库异常？**  
A: 确保应用有数据库文件的读写权限，检查 SQLite3 是否正确安装。

### 群聊问题

**Q: 无法退出群聊？**  
A: 群主需要先解散群聊或将群主身份转让给其他成员。

**Q: 群聊消息发送失败？**  
A: 检查群组成员列表是否正确，确认网络连接正常。

## 🛡️ 安全加固记录（2026-08）

以下为 2026-08 历史版本的加固记录；当前认证与恢复流程以 v1.3.0 单密码指南为准：

### 严重漏洞修复

| 漏洞 | 修复 |
|------|------|
| Go 服务端类型断言可导致进程崩溃（远程 DoS） | 全部改为安全类型断言 + `recover` 兜底 |
| Python 服务端无消息长度限制（内存耗尽 DoS） | 单条消息上限 1MB，超限断开 |
| Python 服务端无连接超时（线程耗尽 DoS） | 认证阶段 30 秒超时 + 登录后空闲超时 |
| 登录密码明文传输 | 新增 `encrypted_login` 加密登录协议（AES-GCM） |

### 高危漏洞修复

| 漏洞 | 修复 |
|------|------|
| 非好友可向任意用户发私聊（Go） | 私聊强制好友关系校验 |
| 重复登录无检查（Go） | `IsUserOnline` + `AddClient` 原子拒绝 |
| 好友关系伪造 | 服务端维护待处理请求，`friend_response` 防伪校验 |
| 群组越权加入 | 仅收到邀请的用户可 `group_join` |
| 群组信息泄露 | `group_info` 仅群成员可查看 |

### 中低危漏洞修复

- 密码哈希改用 **Argon2id + 随机盐**（Go 端原用用户名作盐，已兼容旧哈希迁移）
- 客户端连接非本机服务器时强制校验公钥指纹（防止中间人攻击）
- 历史私聊仅对仍是好友的双方可见
- 用户名/密码长度校验（用户名 2-20，密码 6-64）
- 会话状态/速率限制记录定期清理，修复内存泄漏
- 私钥文件权限加固（0600）
- 日志不再记录消息内容
- 客户端畸形消息过滤，防止接收线程崩溃

> ⚠️ **注意**：连接非本机服务器时，请务必在 `client.py` 中设置
> `EXPECTED_SERVER_KEY_FINGERPRINT`（首次连接本机服务器后从日志获取实际指纹）。

## 服务端加密存储

Python / Go 服务端使用相同的字段级存储加密格式。聊天正文和时间、用户名映射、旧账号密码哈希、群名称、群主、成员列表及群创建时间使用随机 nonce 的 AES-256-GCM。v1.3.0 的 OPAQUE setup、账号记录及客户端已加密的身份备份也受这一层保护；云备份不包含本机信任数据。好友关系、消息参与者和待处理申请里的用户名使用 HMAC-SHA256 索引，不保存可读用户名。

存储密钥默认保存在数据库旁的 `chat.db.key`（32 字节），与 RSA 密钥和网络会话密钥独立。可通过 `CHATROOM_STORAGE_KEY_FILE` 指定数据库目录之外的密钥路径。POSIX 系统默认将数据库和密钥权限设为 0600；Windows 应使用账户权限保护密钥文件。备份加密数据库时必须同时保存对应密钥，并将密钥与可共享的数据库副本分开保管；丢失密钥后无法恢复数据。

升级前先停止旧服务端并备份数据库。新版在监听端口之前，按事务迁移旧账号、聊天和群组等数据，再清理旧空闲页及 WAL。迁移失败会回滚；清理中断会在下次启动继续。密钥丢失、损坏或不匹配时停止启动，不生成替代密钥，也不回退到明文读取。迁移后的数据库只能供支持本版本认证与存储格式的服务端使用；客户端帧协议仍是 v2，但旧认证只保留给尚未迁移账号。

这是敏感字段加密，SQLite 表结构、记录 ID、群 ID、消息类型、关联索引、申请过期时间及记录数量仍可见。服务端运行时会解密数据，属于服务端静态数据保护。原有明文备份、日志以及底层存储已删除块不在此次自动迁移的保护范围内。格式及恢复说明见 [存储说明](docs/STORAGE_ENCRYPTION.md)。

开发与发布流程见 [CONTRIBUTING.md](CONTRIBUTING.md)。
