# 端到端加密

v1.2.0 的桌面客户端在本机加密私聊和群聊正文，服务端只接收、保存和转发密文。登录认证和消息路由继续使用原有的已认证传输协议；传输会话密钥、服务端 RSA 私钥以及数据库存储密钥都不能解开新的端到端密文。

## 首次使用与身份核对

1. 先升级所使用的 Python 或 Go 服务端，再使用新版客户端。
2. 登录时填写**本机加密密钥口令**。它必须与账号登录密码不同，至少 8 个字符，建议使用 12 个以上字符的独立口令。这个口令不会发送到服务端。
3. 首次登录在本机创建身份并登记公钥。联系人也需要先登录新版客户端，建立自己的加密身份，之后才能收发新消息。密钥尚未准备好时会保留输入并停止发送，不会退回明文。
4. 在“端到端加密与密钥…”查看自己的指纹，通过当面、电话等其他可信渠道，与联系人本人核对指纹，再标记为已核对。首次收到的有效身份会固定在本机；首次信任本身不能识别恶意服务端提供的替代公钥。
5. 首次向群聊发送，以及群成员或密钥变化时，需要明确确认接收人。收到群消息时也检查已批准的接收人范围。未批准或验证失败的内容不会作为可信明文显示。

联系人密钥改变会停止发送和验证，必须通过其他可信渠道重新核对。服务端不能自行替换已经登记的账号身份。群成员加入后，只能解密包含其密钥的新消息；移除成员后，之后的新消息不会再为其封装密钥。已经共享给旧成员的消息无法撤回其解密能力。

更换已固定的联系人密钥或批准群成员变化后，旧密钥和旧名单只用于验证**本机此前已经记录过的原始消息**，还必须匹配已保存的封装摘要及服务器编号。尚未记录的旧消息会被阻止，即使服务端声称它来自历史；这能防止已移除成员或已泄露旧密钥伪造新的“历史”。完整密钥备份包含这些观察记录。若群成员确实重新加入，选中该群后在密钥窗口点击“确认当前群接收人…”重新核对当前名单；这不会发送聊天正文。确认后可重新登录以重新读取先前被阻止的消息。

## 本机密钥与备份

密钥文件位于客户端配置目录的 `e2ee/` 子目录，按服务器和账号隔离。私有签名密钥、交换密钥、固定的联系人身份、群接收人批准记录及有限的重放记录一起经过 Argon2id 与 AES-256-GCM 加密。客户端不上传私钥、密钥口令或密钥备份。

- 登录后用“导出加密密钥备份…”保存备份，并将口令与备份分开保管。
- 换电脑时，先选择原服务器、填写原账号，再在登录页用“从密钥备份恢复…”导入。恢复需要导出时的口令。
- 服务器地址或端口变更时，可以明确确认将同一账号的备份迁移至所选服务器；不能借此把其他账号的密钥导入当前账号。
- 更改本机密钥口令不会更改账号密码或身份。原有备份仍使用导出时的旧口令，需要重新导出。
- 如果服务端已有该账号的公钥，而本机没有对应私钥，登录会要求恢复原备份，不会偷偷重新生成或覆盖身份。

**丢失私钥和所有备份后，账号密码、服务端密钥和数据库备份均不能恢复已有端到端消息。**

## 消息格式与两端兼容

服务端通过 `e2ee_v1` 能力声明支持。新版桌面客户端要求该能力，没有能力时拒绝连接并提示升级。已有账号在登记端到端身份后，服务端拒绝该账号的明文发送，也拒绝向已登记身份的接收人发送明文。尚未登记身份的旧账号之间保留旧客户端兼容路径。

每条消息使用独立随机的 256 位内容密钥和 AES-GCM nonce。客户端用临时 X25519 密钥，与每位接收人的静态交换公钥生成共享秘密，再用 HKDF-SHA256 派生独立的封装密钥。私聊包含发送人和接收人的密钥副本；群聊为当时全部已确认成员逐一封装，因此离线消息、发送者历史和分页补取都不依赖服务端掌握内容密钥。

Ed25519 签名绑定版本、随机消息 UUID、发送者、会话类型与目标、发送者公钥、接收人及其指纹、临时交换公钥、nonce、密文和密钥封装。正文 GCM 的附加认证数据绑定消息头；密钥封装同时绑定消息头和接收人。签名输入采用排序键、紧凑分隔和 ASCII Unicode 转义的 JSON，Python 与 Go 通过同一互操作向量验证。

数据库通过新增 `messages.e2ee` 标志区分密文封装和旧消息，避免把恰巧长得像 JSON 的旧正文误判成端到端密文。两个服务端以相同方式保存公钥与密文。实时投递、登录历史、向前补取及向后分页均保持原密文封装。服务端在保存前检查身份、签名、当前接收人集合及帧长度；群成员检查与发送在同一组操作锁内进行。

旧历史不会追溯变成端到端加密，界面会明确显示“旧消息 · 非端到端加密”。不要将旧服务端用于包含新密文的数据库；备份数据库和存储密钥后，使用新版 Python 或 Go 服务端启动即可完成新增表和字段的升级。

## 保护范围与限制

- 保护消息正文；账号、关系、群成员、路由、时间、大小和流量等元数据仍可由服务端观察。
- 不采用双棘轮协议，**不提供长期接收私钥后来泄露时的前向保密**。取得某接收人的私钥及历史密文，可能解开此前发给该身份的消息。临时发送密钥不能消除这一限制。
- 首次公钥信任需要独立渠道核对。恶意服务端仍可以丢弃、延迟、重排消息或拒绝服务；签名不提供服务可用性保证。
- 客户端保存最近 10,000 条已验证消息的签名 UUID 与服务器编号对应关系，拒绝把同一封装换成新编号后重复显示。该检查有保留范围，不代表无限期的全局消息排序或审计保证。
- 每条加密消息的 UTF-8 正文上限为 256 KiB，最多 256 位接收人；完整封装仍受 1 MiB 帧上限约束。
- 解锁后的本机、截图、被恶意修改的客户端及接收人主动泄露正文不在加密所能保护的范围内。

实现使用 PyCryptodome、Argon2 CFFI、Go 标准密码库及固定版本的 Edwards25519 公钥校验依赖，不自行实现底层密码算法。测试覆盖篡改、公钥替换、弱公钥、降级、重放、备份恢复、群成员变化，以及两个真实服务端的离线与历史消息。
