# 会话草稿、待确认消息列表与时区验证

本记录对应 v1.4.0 之后尚未发布的开发分支，承接[聊天区 UI 验证](CHAT_UI_VALIDATION.md)。使用说明见[发送恢复、缓存与搜索](../SEND_RECOVERY_AND_CACHE.md)。

## 行为与回归

本轮新增 22 项 Python / 实际 Tk 回归：

- 6 项草稿回归：私聊、群聊与无选中会话的输入隔离；相同选择不重置输入；撤销栈隔离；迟到确认清除原草稿并保留其他会话输入或已编辑草稿；重新登录后按账号恢复；离群与再入群不复用旧草稿。
- 4 项发送控制回归：正在发送不可移除；移除后的旧查询及操作不能重建记录；旧服务端释放待确认容量且不发送正文；账号 / 端点隔离；重连间隙保留记录且旧定时器不能删除它们。其中前两项合并在同一测试中。
- 6 项原页面列表回归：跨会话选择并只重试所选记录；旧服务端的两次移除确认与输入保留；选择变化取消移除确认；真实断线后的列表保留与操作权限；断开登录销毁摘要控件；展开 / 收起保留阅读锚点或最新消息跟随。
- 5 项时间回归：带偏移时间转换为本地；旧墙钟时间不推断时区；等价时刻与跨格式分组；UTC 到上海的跨日显示及纽约夏令时；真实 Tk 日期、时钟与完整时间详情。
- 1 项 Python 服务端实际收发回归：旧历史时间原值不变，新私聊与群聊均使用 UTC RFC 3339。

既有 Go 私聊 / 群聊去重测试增加 UTC 格式校验。Python / Go 端到端互操作测试增加首次送达、回执查询、重启并切换另一套后端后的时间原值校验。

列表补测复现了展开后丢失最新消息跟随的问题，现按消息身份恢复阅读位置。断线场景另验证连接端点清空后仍使用原会话端点判定记录归属，防止重连间隙隐藏记录或旧定时器误删。旧草稿结构的测试预期已更新为四元组键。

## 验证结果

最终完整回归：579 项 Python / 实际 Tk / Python-Go 互操作测试全部通过，无跳过，耗时 309.059 秒；没有 Tk 回调异常。相较上一轮 557 项新增 22 项。

Go `go vet ./...` 与 `go test -race ./...` 全部通过；后端仅改变新消息生成的时间格式，不迁移已有数据库内容。

Linux 实际 PyInstaller 服务端及客户端均构建成功。客户端包含新增列表模块并通过加密运行时自检；服务端成品通过真实 TCP 群聊、UTC 时间、幂等重试与保存回执的冒烟验证。最终客户端增量构建后再次通过加密运行时自检；源码与两个最终成品通过发布隐私检查（1 个提交、2 个成品）。

## 边界

本轮未实测 Windows 成品及原生中文字体外观。使用进程时区切换的测试在缺少 `tzset` 的平台跳过，其余本地时间和实际控件测试继续运行。旧记录缺少时区，保持原显示值并明确标记；不能凭现有数据恢复其准确 UTC 时刻。草稿与待确认记录仍只在当前进程内存中保留，手动移除记录不撤回消息、不表示保存成功，再次发送可能重复。

本轮未提交、推送或发布，版本号保持 v1.4.0。
