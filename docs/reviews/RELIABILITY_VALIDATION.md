# v1.0.15 可靠性验证记录

日期：2026-10-19。验证对象为 Python 和 Go 两种服务端，使用真实 TCP 连接、协议 v2 认证、加密消息和隔离的临时数据库。压力验证在 Linux、Python 3.12、Go 1.24.5 上执行；Windows / Linux 自动回归使用相同的可靠性测试。

## 已执行场景

| 场景 | 验证标准及结果 |
| --- | --- |
| 每端 8 客户端，各发 100 条群聊、50 条私聊，共 1,200 条 | 所有成功回执对应唯一数据库记录；每个应收用户实时收到一次且正文正确，无异常断线；强制终止再启动后分页历史 ID 与数据库一致 |
| 每端 32 客户端，各发 25 条群聊、10 条私聊，共 1,120 条 | 与上行相同；每端群聊共 800 条，验证跨多页历史 |
| 发送进行中强制终止服务端 | 达到至少 24 个成功回执时终止；收到成功回执的消息全部保留，数据库完整性检查通过，重启后可查回所有已提交消息 |
| 好友申请和群邀请的离线恢复 | 申请提交后终止再启动，离线用户收到申请；接受后再次终止再启动，申请不会重放，待处理表已清空 |
| 连接回收 | 同一账号断开并重新登录 12 次，随后建立并放弃 48 个认证前连接，其中半数发送不完整长度头；正常请求和后续登录仍成功；Linux 文件描述符回到基线加 2 以内 |
| 数据库写入错误 | 用 SQLite 触发器拒绝消息插入，私聊和群聊均返回失败，没有转发或新增消息；移除触发器后，相同请求 ID 可重试成功，各保存一次 |
| TCP 分片 | 将认证帧的长度头、序号、正文与 MAC 分多次发送，随后发送普通帧；每个群成员均收到各消息一次，正文与数据库一致 |
| 异常输入隔离 | 每端处理 44 个错误类型或越权业务请求，状态未被修改；错误 MAC、重放、超长长度、空帧、非法 UTF-8 和 JSON null 均使异常连接关闭，其他用户可继续操作 |

较大规模场景单独执行，默认自动回归使用每端 4 个客户端、168 条消息，控制日常 CI 时长。每种服务端有 7 个可靠性测试，均位于 [`tests/test_system_reliability.py`](../../tests/test_system_reliability.py)。复现命令见[开发说明](../../CONTRIBUTING.md)。测试进程不会使用现有聊天数据，固定 Go 端口 `12346` 被占用时会拒绝运行。

## 完整回归

Linux 上使用 Tk 9.0.4 的完整回归为 113 项，全部通过，未跳过 Go 测试；其中包括原有真实 Tk 界面、群管理并发、存储迁移、协议和互操作测试，以及本次新增的 14 项进程级可靠性测试。Go 的 `go vet ./...` 和 `go test -race -count=1 ./...` 均通过。发布流水线同样在 Windows / Linux 运行完整回归，再生成平台程序。

发布流水线的 Windows / Linux 回归及所有平台构建已通过。下载实际发布的 Linux Python / Go 服务端，再次执行并发收发及重启、发送中强制终止、写入失败重试和 TCP 分片，共 8 项检查均通过；Linux 客户端程序在 Xvfb 下正常显示登录窗口。20 个附件齐全，校验文件中的 19 个条目均与 GitHub 附件摘要一致，下载文件的 SHA-256 及源码包关键文件已核对。

独立构建曾在旧的并发登录测试中误报：收到 `login_result` 不代表会话已完成初始化，而 `GetClient` 只返回已就绪会话。后续测试修正增加显式激活屏障，先确认重复登录未移除预留，再等待 `history_end` 后检查就绪会话；不依靠增加睡眠时间。旧断言在延迟激活时稳定失败，修正后连续 5 次竞争检测通过。这项修正仅涉及测试，v1.0.15 的服务端程序无需变更。

## 本轮发现并修复

Go 服务端在仅私钥丢失时会重新生成密钥并覆盖已有公钥，改变客户端固定的服务器身份。新增测试先在旧代码上确认失败，再验证修复后停止启动、原公钥不变、恢复原私钥即可重新加载相同身份。

已有 Go 私钥的 POSIX 权限过宽时，旧代码不会收紧；回归测试显式设置 `0644` 后确认旧实现失败，修复后变为 `0600` 且密钥不变。新私钥从创建时即使用 `0600`，以独占方式避免覆盖已有私钥。

## 证据边界

以上是已执行的负载和故障场景，不代表零缺陷证明，也不等同于 32 人以上、数天持续运行、所有网络环境和硬件的验证。并发场景使用协议客户端；界面操作由项目独立的真实 Tk 回归覆盖。

成功回执表示数据库已提交。进程中断前没有收到回执的请求仍可能已经保存，本轮不将这部分记录当作消息丢失，也不声称跨断线重发具有恰好一次语义。强制终止测试验证进程崩溃恢复，不模拟物理断电；SQLite 触发器验证写入错误分支，不等同于真实磁盘写满或文件系统故障。

本轮在这些已执行场景中未观察到确认消息丢失、实时重复投递、越权修改、历史与数据库不一致或连接资源持续增长。
