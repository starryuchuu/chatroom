# 桌面、消息复制与渲染验证

本记录对应 v1.4.0 之后的开发分支，承接[草稿与时区验证](DRAFTS_SENDS_TIME_VALIDATION.md)。改动包括原页面待确认浮层与大字体布局、按需原生只读选择及复制、日期与作者控件的延迟建立。版本号未变，不发布新版本。窄宽度浮层自动收起时间与状态列，在所选记录详情中展示完整信息；表格使用小字号并按像素省略长值，防止相邻单元格内容拥挤。

## 覆盖与运行方式

新增 8 项真实 Tk 复制 / 行复用回归、1 项桌面矩阵回归、1 项解释器释放回归及 1 项搜索回调交错回归。矩阵在 900×700 窗口的五档缩放和深浅主题下检查控件在祖先窗口内完整显示、输入区与聊天区可用、待确认记录可读、Unicode 输入及复制。验证过程中修复了高 DPI 待确认面板挤出输入按钮的问题，并在 Tcl/Tk 8.6 中复现和修复了表情前缀导致搜索高亮偏移的问题；`Text` 的 `+Nc` 按字符前进，不能用 Tcl 8 的 `string length` 替代 Python 匹配偏移。

- Linux 有中文字体的原生 Tk 8.6 环境运行桌面矩阵；另一套 Tk 9 环境验证复制与搜索行为。两者都使用隔离设置和合成内容。
- `python client.py --check-desktop-ui <输出目录>` 与冻结客户端使用相同检查。JSON 记录平台、字体、缩放、主题、剩余聊天高度与工具栏是否换行。
- Windows 路径检查所选字体的实际中文字形，用 Win32 `WM_CHAR` 验证 Unicode 提交，保存十张截图。Linux 可在 ImageMagick 可用时保存截图。
- 发布构建工作流在 Windows / Linux 成品上执行检查，并将报告和截图作为 `ui-validation-windows` / `ui-validation-linux` 上传；这些是 CI 检查产物，不是 GitHub Release。

本地完整回归 588 项通过，耗时 323.768 秒，无跳过或 Tk 回调异常；浮层列宽与所选详情调整后，13 项相关界面回归继续通过。Tk 8.6 的 22 项复制 / 搜索 / 缩放定向验证与 Tk 9 的 21 项复制 / 搜索验证均通过。Linux 客户端实际成品通过加密自检及十组桌面矩阵。源码、实际成品、平台结果及日志以对应 PR 的检查和上述产物为准。完整回归使用新的客户端代码与已验证的 Python / Go 后端；后端实现未因复制或渲染调整而变化。

Windows 实测还发现系统区域编码无法处理 `strftime` 中的中文日期字面量，日期标题现直接组合年、月、日。Win32 原生菜单的模态循环需要人工选择才能退出，Windows 自动化仅替换菜单的弹出调用，继续验证真实 Tk 绑定、菜单权限与命令；Unix 仍实际弹出菜单。相关 Windows 定向检查已提前到完整回归之前，以便及时输出失败回溯。

Windows 完整回归还复现了自检返回后，残留 Tk 对象被网络线程触发的循环回收处理而导致解释器退出的问题。自检现在逐轮在 Tk 主线程关闭并释放视图、窗口及变量，显式回收；弱引用回归断言返回后不再保留解释器所属窗口。

Windows 键盘回归现在明确设置输入框焦点后再合成回车事件，避免把未派发的键盘事件误判为搜索逻辑失败。构建与完整回归并行执行，以便更早反馈成品问题；发布仍显式依赖同次运行的计划、测试与构建全部通过。

并行 CI 复现了搜索导航被晚到防抖回调重置的问题。立即刷新现使旧调度失效；新增回归显式执行被延迟的旧回调，确认当前结果仍保持在第二条，不依赖睡眠或机器速度。

## 性能测量

`scripts/benchmark_client_render.py` 现在为合成消息提供实际时间戳，支持 `--repeat`、`--authors` 和 `--lines`。对照使用本轮前的 Git 索引源码快照，双方使用同一个测量脚本、消息内容、Python / Tk / 字体环境。报告中比较重复采样中位数，不以跨机器耗时设测试阈值。

原先的无中文字形 Tk 9 环境中，2,000 条插入的单作者会话首次渲染中位数为 387.39 → 243.70 ms；10,000 条插入（缓存保留 2,000 条）为 417.34 → 228.69 ms；多作者、四行正文为 497.85 → 448.37 ms。这些早期测量用于定位控件创建开销；中文字体环境应单独比较，不混算平台结果。行数上限与正文缓存预算保持不变，Python 分配测量不代表 Tcl/Tk 原生内存或进程 RSS。

在无其他本地验证 / 构建负载的 Python 3.13.5、Tk 8.6、Noto Sans CJK SC 环境中，最终每项各采样三次：

| 场景 | 优化前首屏中位数 | 优化后首屏中位数 | 优化后不变重绘 |
| --- | --- | --- | --- |
| 插入 2,000 条，单作者单行 | 660.535 ms | 363.246 ms | 10.197 ms |
| 插入 10,000 条，保留 2,000 条，单作者单行 | 660.309 ms | 368.639 ms | 9.085 ms |
| 插入 2,000 条，5 位作者、4 行正文 | 689.525 ms | 572.096 ms | 10.134 ms |

单作者首屏下降约 44%–45%，多作者、多行下降约 17%；每次显示最多 120 行，不变重绘继续复用全部行。这里的首屏计时覆盖创建与布局，使用 `tracemalloc` 的运行与原生桌面主观响应时间不能直接等同。

## 验证边界

原生字符提交测试覆盖输入提交后的文字内容，不能证明真实输入法的预编辑、候选窗口、切换快捷键或第三方输入法体验。截图与自动检查同样不能替代这些人工操作。系统剪贴板只在明确复制时写入，其跨应用留存由操作系统管理。

通过验证分支进行 Windows CI，无合并、版本标签或发布操作。
