# 请求生命周期、业务拆分与消息列表测量

## 改动范围

- `SessionContext` 统一 socket、账号、会话和群成员代次的归属判断；`RequestToken` 提供分页及增量同步的请求身份。Python / Go 支持可选的历史分页请求 ID、控制帧回传和逐条历史标记。旧请求仍被接受，新客户端在旧服务端上超时后要求重新连接。
- Python 的 18 个消息分支抽成 `server_handlers/` 中的好友、群管理、消息处理器，通过 `HandlerServices` 显式接收共享状态、锁和存储/发送操作。认证、在线发布及断开清理仍由入口协调；处理器的提前退出保留原有锁释放和异常处理路径。
- CI 使用一个工作流执行测试、调用可复用构建，再在满足条件时发布同次运行的产物。PR 和非 master 分支不能进入发布任务。发布任务独立取得写权限，并执行发布隐私检查。
- 登录卡片布局独立为 `LoginCard`；`MessageList` 复用已有行，替换内容变化的行，每个会话最多显示 120 行。滚动边缘自动切换重叠窗口，模型保留完整消息及游标；点击新消息入口返回最近窗口。

## 测量

使用 `scripts/benchmark_client_render.py`，无需服务端或个人配置，全部消息为合成数据。在同一 Linux / Xvfb 环境比较 v1.3.4 原渲染器与重构后的渲染器：

| 场景 | 原渲染器 | 重构后 |
| --- | --- | --- |
| 100 条消息，不变内容重绘 | 151.7 ms，全部重建 | 6.8 ms，复用 100 行 |
| 100 条消息，插入一条较早消息 | 187.3 ms，全部重建 | 17.0 ms，复用 100 行 |
| 200 条消息，不变内容重绘 | 336.7 ms，显示 200 行 | 10.0 ms，显示并复用 120 行 |
| 1,000 条消息 | 本地 X11 原全量渲染触发原生控件尺寸错误 | 首次 307.7 ms，后续不变重绘 8.1 ms，显示 120 行 |

这些是一次参考测量，不作为跨平台计时断言。200 条以上的比较同时包含显示窗口大小变化。脚本的 Python 分配峰值只覆盖测量期间的 Python 分配，不包含预先构建的模型和 Tcl/Tk 原生内存；完整消息仍保留在模型中，不能据此声称进程总内存已有固定上限。

```bash
xvfb-run -a python scripts/benchmark_client_render.py --messages 100 200 1000
```

## 验证边界

回归覆盖取消、超时、旧响应重排、原游标重试、同群退群再入、跨连接/账号失效、两种服务端的关联回传，以及千条消息的行数上限、前后滚动、控件复用、阅读锚点和新消息入口。既有认证预留、群权限、故障恢复和互操作测试继续作为业务拆分的验证基础。

补充回归覆盖同请求 ID 的错误会话范围、自动入群与手动分页交错、发送失败后的重试、晚到历史对模型及未读数的影响、增量同步期间分页结束，以及会话重建或账号切换后排队滚动回调的失效。真实 Tk 用例验证千条历史中的单行解密恢复与多行消息的阅读锚点；服务端用例验证非法请求 ID 被拒绝后连接仍可重试、128 字符 Unicode ID 的回传，以及处理器存储失败后的授权状态与锁释放。

发布计划测试在隔离的临时 Git 仓库中执行真实 CLI，检查普通提交、版本提交、首次推送、PR、手动发布、非主分支、版本不一致及缺失基准提交，并读取实际 Actions 输出。新增用例发现并修复了版本校验差异：计划脚本与发布步骤现在均只接受 ASCII 数字形式的 `vX.Y.Z`。

GitHub 工作流在本地通过 actionlint 检查；实际远程执行需在提交推送后验证。Linux 成品构建及加密运行时自检用于确认新增静态模块可被打包；这些检查不能替代 Windows 的实际发布构建。

最终本地验证：新增 23 项 Python 测试后，506 项 Python / 真实 Tk / Python-Go 互操作回归全部通过，无跳过（262.188 秒）；Go `vet` 和全套 `-race -count=1` 检查此前通过，新增 Go 请求 ID 边界用例随历史分页测试再次通过 `-race -count=1`。Linux 客户端、服务端实际构建成功，客户端成品通过加密运行时自检，两个成品及源码通过隐私检查。发布计划 CLI 的七项集成测试纳入完整回归，actionlint 1.7.7 检查三个工作流通过。以上为发布前本地验证；远端构建与附件以 v1.4.0 发布工作流的实际结果为准。
