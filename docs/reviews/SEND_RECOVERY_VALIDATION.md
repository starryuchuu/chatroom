# 发送恢复、缓存与搜索验证

本记录对应 v1.4.0 之后的开发分支，尚未发布；使用和协议说明见[发送恢复、缓存与搜索](../SEND_RECOVERY_AND_CACHE.md)。

以下为后续聊天区 UI 调整之前的验证；新一轮界面改动与回归见[聊天区 UI 验证](CHAT_UI_VALIDATION.md)。

## 实现与回归范围

- Python / Go 在消息写入同一事务中保存账号归属和内容绑定的回执；重试保留幂等键、更换传输请求 ID，并返回原编号与原时间，不重复投递给接收人。覆盖并发重复提交、内容冲突、回执写入失败时消息回滚，以及查询的账号与会话隔离。
- 客户端区分发送中、结果待确认、查询中和可重试。覆盖超时释放发送入口、确认丢失后恢复显示、相同输入防止重复提交、旧回执与定时器失效、重连只查询不自动重发、群生命周期和账号切换清理，以及待确认内容的数量与大小限制。旧服务端保持人工确认路径。
- 每个会话限制 2,000 条 / 8 MiB 正文缓存，账号总预算为 8,000 条 / 32 MiB。覆盖 UTF-8 大正文、较旧分页淘汰较新正文、阅读锚点与摘要保留、最近历史重新加载、非当前会话的全局淘汰、未读元数据保留、历史重载与重复实时消息提醒。
- 搜索仅处理当前缓存中验证通过的消息正文。覆盖字面匹配、Unicode、大小写、结果上限、跨 120 行窗口跳转、关键词高亮、Ctrl+F 保留输入、快速回车使用当前关键词，以及切换会话、账号和清空缓存后释放结果引用。
- 两个真实服务端均验证私聊及群聊去重；强制停止后分别切换 Python→Go、Go→Python，保留原数据库、存储密钥和 RSA 身份，回执查询和重复发送仍返回原保存结果。

## 本地验证结果

在 Linux / Xvfb 环境使用 Python 3.12.14、Go 1.27.3：

- 相比已发布的 v1.4.0 新增 39 项 Python 回归，最终完整 545 项 Python / 真实 Tk / Python-Go 互操作测试通过，无跳过，耗时 283.008 秒。没有 Tk 回调异常。
- Go `vet ./...` 与全套 `go test -race -count=1 ./...` 通过，包含新增的四项回执回归及私聊、群聊与并发子场景。
- Linux 客户端、服务端实际 PyInstaller 构建成功，确认包含新增搜索、发送控制器和服务端回执模块。客户端成品通过加密运行时自检；服务端成品通过真实连接的回执查询、重复提交及单条持久化烟雾测试。
- actionlint 1.7.7 检查三个工作流通过。源码附件和校验清单包含新增 `send_receipts.py`。
- 源码与两个 Linux 成品通过发布隐私检查；本轮没有新增 Git 提交，已发布 HEAD 的公开别名检查保持通过。

首次完整回归暴露了三项加密测试模拟视图缺少新缓存接口的问题，已补齐模拟接口；最终结果来自修正后的整套重跑。

## 合成消息测量

使用 `scripts/benchmark_client_render.py --messages 2000 10000`，不读取真实账号、配置或服务端：

| 依次插入消息数 | 最终缓存条数 | 正文及固定开销计量 | 模型构建 Python 分配峰值 | 显示行数 | 不变内容重绘 |
| --- | --- | --- | --- | --- | --- |
| 2,000 | 2,000 | 318,896 B | 622,031 B | 120 | 9.814 ms |
| 10,000 | 2,000 | 320,002 B | 793,892 B | 120 | 9.624 ms |

这是一组短合成正文的一次本地参考测量，不是跨平台性能阈值。模型分配测量在插入前开启、插入后结束；渲染分配另行测量。它们不包含进程基线、Tk 原生分配、密钥库、所有未读元数据或服务端资源，不能等同于进程总内存上限。
