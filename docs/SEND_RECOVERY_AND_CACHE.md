# v1.5.0：发送恢复、消息缓存与搜索

本文描述 v1.5.0 的发送恢复、缓存和桌面交互。

## 发送结果核对

发送后仍保留输入，服务器的保存确认只表示数据库已提交，不表示对方已读。15 秒未收到确认时，消息进入“待确认”状态，发送入口释放，可以继续编辑或发送其他内容。

支持 `message_receipts` 的 Python / Go 服务端可查询该条消息的保存结果。已保存时恢复原消息编号、时间与本机显示，仅清空原会话中仍与原文一致的输入或内存草稿；暂未找到回执时在待确认列表提供“重试所选消息”。重试保留原 `idempotency_key`，重新生成传输请求的 `request_id`，服务器返回同一保存结果并避免重复投递给接收人。重试保留原加密封装，并在入队前重新检查本机加密身份、联系人固定密钥与群接收人批准，持有共享信任锁直到入队；信任已变化时保留待确认记录并停止重试。查询本身超时可以再次核对，不猜测保存成功或自动重新发送。

异常断线后的自动重连先核对回执，不自动重发正文。手动断开、切换账号、退出或离开对应群聊会清理待确认记录；这些记录仅保存在当前进程内存中，不是持久发件箱。最多保留 20 条、合计 8 MiB 的待确认数据，达到上限时保留输入并要求先处理既有结果。旧服务端仍可使用，但没有安全查询与去重保证，需查看历史后自行确认结果，客户端不会自动重复发送。

## 会话草稿与待确认列表

草稿只在当前进程内存中按服务器、账号和 `ChatKey` 隔离。切换会话保存当前输入并恢复目标草稿，私聊用户名与同名群 ID 不共用草稿；重新选择当前会话不修改输入。切换或清空输入会重置输入框的撤销记录，避免撤销操作恢复其他会话文字。手动断开后，重新登录同一账号并选择原会话可继续编辑；退出进程后不保留。离开群聊会清除该群草稿，再入群不恢复旧草稿。

迟到的保存确认只清除原会话中仍与发送正文一致的草稿，既不清空其他会话输入，也不清除已修改的草稿。发送失败继续保留输入。

点击输入区“待确认消息 (数量)”在原页面展开浮层列表，显示本账号所有会话的待确认记录，包括会话、首次发送的本地时间、状态和短摘要。选中任意一条进行核对或幂等重试；正在发送、正在核对或连接中断时，相应操作禁用。列表可以收起，未处理记录继续保留。浮层不占用输入区与聊天区的布局高度，展开和收起保持原阅读锚点或最新消息跟随；自动重连间隙仍显示原会话的记录，可以查看和移除，恢复连接前禁用查询和重试。

旧服务端无法自动核对时，可先查看历史，再选择“移除本机记录…”。移除需要在列表内再次明确确认，并提示消息仍可能已保存、再次发送可能重复；正在发送的记录不可移除。移除只释放本机待确认记录，不撤回消息、不改变服务端回执、不代表保存成功，也不清空草稿。晚到的查询或旧列表操作不能重新建立已移除的记录。

## 消息时间

两套服务端新发送的私聊、群聊及端到端加密消息统一使用 UTC RFC 3339 时间（如 `2026-10-26T22:15:00Z`）。时间由服务端生成，历史、同步、回执查询及幂等重试均保留首次保存的值，不按请求时刻重写。客户端把带时区的时间转换为本机时区，再显示时分、日期分隔和连续作者分组；展开详情同时显示本地偏移与原始时间。

旧记录或旧服务端提供的不含时区时间保持原墙钟值，不猜测为 UTC 或客户端本地时间，详情注明“旧记录，时区未记录”。新旧格式可以混合加载，消息排序和分页继续依据消息 ID；跨格式不合并连续作者。此改动不改写数据库已有时间，不影响加密封装。

## 缓存与历史加载

每个会话保留最多 2,000 条消息，按 UTF-8 正文加固定开销计量不超过 8 MiB；账号内所有会话共用 8,000 条 / 32 MiB 的正文缓存预算。全局预算优先淘汰最近最少使用的非当前、非分页会话；再次选中会重新加载最近历史。侧栏保留短摘要，已读、未读编号和分页状态独立处理。服务端历史不会因客户端淘汰缓存而删除。

阅读较早消息时优先保留当前历史窗口，新消息继续更新摘要、未读与新消息入口。加载更多旧历史导致较新正文被淘汰时，使用“返回最新消息”从服务器重新取最近一页；无法连接时不能重新加载已淘汰正文。向更早方向继续加载仍使用服务器分页游标。缓存正文、搜索结果和原生控件均受各自上限约束，但这些数值不是整个进程的内存上限，未读编号、本机信任及防重放记录仍有各自的生命周期。

正文缓存的去重索引随缓存淘汰；当前账号另保留最近 10,000 个会话/消息编号用于避免重复实时消息再次提醒。密钥库既有的签名、接收人批准和已观察封装记录不因缓存淘汰而清除，重新加载仍执行完整验证。

## 消息区与会话操作

聊天顶部保留“搜索”和“更多”。通过“更多 → 加载更早消息”读取历史，群聊的成员与设置仍从“更多 → 群聊信息”进入。加载期间与历史耗尽时，菜单显示对应状态；“返回最新消息”统一使用聊天区底部入口，不再同时占用顶部空间。

有效时间戳按日期分段；同一日期内连续五分钟内、作者与安全状态一致的消息合并重复作者信息。窗口边缘始终补足日期和作者上下文。时间简写为时分，点击时间或安全标记可在原消息下展开完整时间与安全说明；旧消息和验证失败提示继续明确标识。滚动锚点使用消息正文，日期与作者行显隐不应改变正在阅读的内容。

## 选择与复制消息

点击正文即可使用原生只读文本选择，支持拖选、Ctrl+A 全选正文和 Ctrl+C 复制所选文字；右键或 Shift+F10 打开“复制所选文字 / 复制整条消息”。复制整条消息只包含正文，不添加作者、时间或安全提示。选择文本不能修改消息，粘贴、剪切和键入不改变原文或草稿；Esc 结束选择并返回输入区。搜索高亮中的文字也支持相同操作。

正文平时保留轻量显示控件，仅在开始选择时创建一个文本覆盖层；选择另一条、切换会话、缓存淘汰或退出会释放原选择控件及引用。复制仅在明确操作时写入系统剪贴板；系统剪贴板由操作系统及其他应用管理，离开本程序后其中内容可能继续保留。

## 缩放与渲染

大字体时工具栏按可用宽度换行，聊天标题区与输入提示采用更紧凑的布局，搜索期间保留输入并临时收起一部分输入高度。待确认列表浮层不会把输入按钮挤出窗口。Treeview 行高跟随实际字体高度，避免固定行高裁切文字。

日期与重复作者控件按实际显示需要创建，不为每条消息先建立再隐藏；时间在行建立时解析，宽度未变时不重复配置所有正文控件。单会话仍保留最多 120 个显示行，不以后台预加载全部历史换取首屏速度。合成渲染测量支持不同消息数、作者数、多行正文及重复采样；测量不作为跨平台耗时保证。

## 当前会话搜索

点击聊天区“搜索”或按 Ctrl+F，在原页面搜索当前会话已加载的消息正文。搜索栏持续说明范围，并显示当前位置、结果数及“上一个 / 下一个”。支持字面关键词、大小写不敏感匹配和高亮；回车跳到下一处，Shift+回车跳到上一处，Esc 关闭。立即搜索后旧防抖回调失效，后续导航不会被重置回第一条。关闭时恢复打开搜索前的阅读位置；原消息已被缓存淘汰时保留当前视图，不重新请求或重建旧会话。原本跟随最新消息时，关闭搜索后继续跟随。查询最多 256 个字符，每次展示最多 1,000 处匹配，超出时用 `+` 标明，可缩小关键词范围。

搜索不会上传查询词、保存明文索引、触发全库扫描或搜索其他账号。验证失败的消息提示不进入正文搜索；旧消息继续显示其原有加密标记。搜索更早记录需先在“更多”中加载历史。切换会话或账号清空查询与结果，缓存变化使结果重新计算；阅读位置只保留消息身份与像素偏移，避免额外持有已淘汰正文。无结果时导航按钮禁用，窗口宽度变化时当前高亮随正文宽度调整。

## 协议与存储

`public_key.capabilities` 新增可选 `message_receipts`。发送方可为 `private_chat` / `group_chat` 添加 32 位小写十六进制 `idempotency_key`；缺省时保留旧行为。键绑定当前认证账号及首次保存的完整会话和内容，复用键修改内容会被拒绝。

查询使用 `message_status_request`：携带独立的 `request_id`、原 `idempotency_key`、`chat_type` 和 `target`。`message_status_result` 回传这些关联字段及 `success`；成功时 `status` 为 `saved` 或 `not_found`，前者另含原 `message_id` 和 `timestamp`。查询只返回当前认证账号自己发送的回执，不返回聊天正文。

新增 `send_receipts` 表，与消息写入同一事务，插入回执失败会回滚消息。发送者、目标及请求键使用存储查询 HMAC；内容指纹也使用带独立域前缀的 HMAC，端到端封装先做跨语言一致的规范 JSON 编码。回执不保存另一份聊天正文或密码，时间仍来自加密消息表。Python / Go 可以在停止旧进程后顺序使用同一数据库、存储密钥和 RSA 身份，保留去重结果；不支持两个服务端同时使用同一数据库。

本改动不改变传输 v2、存储字段加密格式或 OPAQUE / 端到端身份格式。新增表随数据库一起备份；部署发送恢复功能时应同时更新客户端与服务端。手动删除回执会失去对应请求的去重保证。
