# 服务端存储格式 v1

存储格式与网络协议独立。Python `storage.py` 与 Go `internal/database/storage.go` 使用同一字段格式，传输帧协议仍为 v2。v1.3.0 新增认证表及 OPAQUE 运行时依赖，详见[单密码指南](SINGLE_PASSWORD.md)。

## 保护范围

| 数据 | 保存方式 |
| --- | --- |
| 聊天正文、聊天时间 | 随机 AES-256-GCM |
| 用户名映射、旧账号 Argon2 密码哈希或 OPAQUE 标记 | 随机 AES-256-GCM |
| OPAQUE setup、账号注册记录、客户端加密的身份备份 | 随机 AES-256-GCM；身份备份另有客户端加密层 |
| 群名称、群主、成员 JSON、创建时间 | 随机 AES-256-GCM |
| 用户查询、好友关系、消息参与者、待处理申请的用户标识 | HMAC-SHA256 不可读索引；用户名只保存在加密映射表 |
| 表结构、记录 ID、群 ID、消息类型、索引关系、请求过期时间和数量 | 可见元数据 |

服务端运行时可解开这一层存储加密。v1.2.0 新增的端到端消息在解开存储层后仍是客户端密文；服务端存储密钥不能解开其正文。旧消息和账号、关系等敏感字段仍可由服务端读取。存储层本身不属于端到端加密或整个文件系统加密，也不认证数据库中的所有结构和关系。不要将密钥和数据库一起交给其他人。端到端密钥及恢复说明见 [END_TO_END_ENCRYPTION.md](END_TO_END_ENCRYPTION.md)。

## 密钥与编码

- 独立随机 32 字节主密钥，默认位于 `<数据库路径>.key`。`CHATROOM_STORAGE_KEY_FILE` 可指定外部路径。
- 加密子密钥：`HMAC-SHA256(master, "chatroom/storage/v1/encryption")`。
- 查询子密钥：`HMAC-SHA256(master, "chatroom/storage/v1/lookup")`。
- 用户名索引：`u1:` 加查询子密钥对原始 UTF-8 用户名计算的 HMAC-SHA256 十六进制串，大小写和空格保持原意。
- 密文字段：`enc1:` 加标准 Base64 编码的 `12 字节随机 nonce || ciphertext || 16 字节 GCM tag`。
- AAD：字节前缀 `chatroom-storage-v1` 加一个零字节，后接各部分的 UTF-8 字节长度（十进制）、冒号及 UTF-8 内容。长度前缀防止字段拼接歧义。
- 常规字段的 AAD 部分为表名、列名、行标识；用户名映射为 `names` 和用户名索引；密钥校验为 `meta` 和 `key_check`。
- 聊天正文 AAD 为 `messages`、`message`、消息 ID、聊天类型、发送者索引、接收者索引、群 ID；缺省字段使用空串。不同消息行或会话间替换密文会验证失败。
- `storage_meta` 保存格式版本、加密密钥校验值及待清理标记；`storage_names` 保存索引和对应的加密用户名。已迁移数据库不接受明文字段，读取失败不会回退为明文。

## v1.3.0 OPAQUE 账号存储

- `opaque_meta(key, value)` 持久保存 `setup_v1`，其值以 `opaque_meta` / `setup_v1` 为上下文加密；已有 OPAQUE 账号时缺少 setup 会拒绝启动。
- `opaque_accounts(username, record, backup, generation)` 使用原用户名查询 token。注册记录和规范 JSON 身份备份分别以表名、列名及 token 为 AAD 加密，代次从 1 开始，用于原子改密检查。
- OPAQUE 账号的 `users.password` 加密保存固定禁用标记，旧认证路径必须拒绝该账号；尚未迁移账号保留原哈希，显式迁移通过 CAS 原子替换。
- 解开服务端存储层只得到客户端加密的身份备份；它不包含联系人信任、群批准或重放状态。身份恢复与完整离线备份的区别见[单密码指南](SINGLE_PASSWORD.md)。

## 升级与恢复

1. 停止旧服务端，备份数据库及原有 RSA 密钥。旧备份仍为明文，请妥善保护。
2. 启动新版服务端。首次生成独立存储密钥，事务中按 256 行分批迁移；所有转换和版本标记一起提交，失败则回滚。
3. 通过安全删除、WAL 检查点和 `VACUUM` 清理数据库里的旧空闲页。清理完成前不监听端口；中断后会根据标记继续。
4. 备份迁移后的数据库、对应存储密钥及原 RSA 密钥，分别妥善保管。OPAQUE setup 和账号记录包含在数据库中；顺序切换新版 Python / Go 时使用同一数据库、存储密钥与 RSA 身份，因为账号认证和身份备份绑定服务端公钥指纹。

密钥缺失、损坏或不匹配时，服务器停止启动，不会为已加密数据库生成替代密钥。恢复正确密钥再启动；没有正确密钥无法恢复。RSA 密钥更换不会改变存储密钥，但会改变 OPAQUE `server_id` 及客户端服务器信任，不能当作无影响替换。迁移后的数据库禁止交给旧服务端打开；回退旧程序需要恢复升级前的完整备份。

加密不清除原有明文备份、日志、操作系统交换文件或底层存储已删除块。需要覆盖这些范围时，应另外使用磁盘加密及相应备份策略。
